\section{Executive Summary}

This report documents the cleaned EDA outputs generated from the drive-test dataset. The cleaning strategy used a 70\% missing-value threshold while protecting important time, location, activity, and event fields. The current evidence shows that the usable measurements are mainly LTE, WCDMA, activity, event, and GPS fields. Therefore, the strongest project direction is \textbf{LTE/WCDMA Drive-Test QoE Anomaly Detection and Root Cause Analysis}.

\begin{infobox}{Main conclusion}
The report outputs support LTE throughput modeling, LTE carrier aggregation optimization, event-window RCA, MO call/CSFB analysis, WCDMA quality analysis, and route-based anomaly mapping. Direct 5G NR PCI/RSI planning validation should not be the main project direction unless a matching Fiji/Nadi NR planning file and usable NR measurements are obtained.
\end{infobox}

\section{Recommended Project Direction}

The outputs suggest two clean project branches. The first branch is an LTE download-performance branch using LTE KPIs, throughput, CA status, events, and location. The second branch is a WCDMA/MO-call branch using WCDMA RSCP/EcNo, CSFB/call RAT, call activity status, setup timing, and event windows.

\begin{successbox}{Recommended project title}
\textbf{Drive-Test QoE Anomaly Detection and Root Cause Analysis for LTE/WCDMA Mobility Networks}
\end{successbox}

Recommended modules:
\begin{itemize}
    \item \textbf{LTE throughput prediction:} predict expected downlink throughput from radio, scheduling, CA, and resource features.
    \item \textbf{Throughput anomaly detection:} flag samples, sessions, or PCIs where real throughput is much lower than expected.
    \item \textbf{Carrier aggregation optimization:} evaluate whether CA activation, carrier count, and SCell quality improve throughput.
    \item \textbf{Event-window RCA:} inspect KPI behavior before and after RACH, handover, CA, and WCDMA active-set events.
    \item \textbf{MO call and CSFB RCA:} explain call success/failure using WCDMA quality, call setup timing, events, and session-level context.
    \item \textbf{Route dashboard:} map RSRP, SINR, throughput, PCI/PSC, event density, and bad sessions.
\end{itemize}

\section{Cleaned Row-Level Dataset}

\subsection{drive\_clean\_base.parquet}
The Parquet file is the cleaned row-level dataset. Parquet is a compressed columnar analytics format, which is better than Excel for wide ML/EDA datasets because it preserves data types, loads faster, and stores large tables efficiently.

\begin{infobox}{Why Parquet instead of Excel?}
Excel is useful for small reports and manual review, but Parquet is better for the cleaned analytical dataset. It is compact, type-safe, fast to load, and suitable for ML pipelines. Excel may become slow, lose data types, or mishandle long identifiers and timezone-aware timestamps.
\end{infobox}

This file should be treated as the clean base source for specialized tables rather than the final ML table itself. Recommended derived tables include LTE samples, WCDMA samples, activities, events, locations, sessions, LTE neighbors, and WCDMA cells.

\section{Final Recommendation}

The project should proceed as an LTE/WCDMA QoE anomaly detection and RCA project. The cleanest roadmap is:
\begin{enumerate}
    \item Use \texttt{session\_summary.csv} to split sessions into LTE-DL and MO/CSFB branches.
    \item Use \texttt{drive\_clean\_base.parquet} as the row-level source.
    \item Use \texttt{events\_long.csv} for event-window RCA and event-derived ML features.
    \item Use \texttt{lte\_summary\_by\_pci.csv} and \texttt{wcdma\_summary\_by\_psc.csv} to prioritize bad PCIs/PSCs.
    \item Restore only the selected sparse KPIs needed for application-throughput, handover, call setup, and CSFB analysis.
    \item Exclude the current NR planning comparison from the main story until the correct planning file and usable NR measurements are available.
\end{enumerate}
